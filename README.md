# OCS 自建 AI 题库（精简版）

自建的题库服务，替代 [OCS 网课助手](https://github.com/ocsjs/ocsjs) 默认的收费题库。
自己接 DeepSeek 大模型答题，答案缓存在本地，答一门课约几毛钱。

**只用 Python 标准库，不需要 pip 安装任何包。**

```
题目 ──> 本地 SQLite 缓存 ──命中──> 直接返回（0 费用）
                │未命中
                v
          DeepSeek API ──> 清洗答案 ──> 写入缓存
```

## 快速开始

```bash
# 1. 配置
copy .env.example .env
# 用记事本或 VS Code 打开 .env，填入 DEEPSEEK_API_KEY

# 2. 启动
python run.py
```

或直接双击 `启动.bat`。

## 项目结构

前后端分离，后端只输出 JSON，页面是独立的静态文件。

```
run.py                启动入口：横幅 + 拉起 HTTP 服务
server/               后端
├── config.py           读/写 .env、运行时常量、prompt
├── store.py            SQLite 答案缓存 + 统计
├── llm.py              调模型、拼 prompt、清洗答案
├── matching.py         归一化、Dice 相似度、答案对齐到选项
├── detector.py         非题目识别（课件正文拦截）
├── service.py          一次查询的业务编排
└── api.py              路由 + 静态文件 + /api/status + /api/cache
web/                  前端
├── index.html          页面结构
├── style.css           样式
└── app.js              拉 /api/status + /api/cache、保存 Key、手动测试
```

依赖方向是单向的，只能从上往下：

```
api -> service -> llm / matching / detector / store -> config
```

`config` 最底层，谁都能用它，它不 import 任何人。这样不会出现循环导入。

**改配置别写 `from .config import API_KEY`**——那是快照，网页上保存新 Key 后不生效，
要用 `config.API_KEY` 这种属性访问。原因写在 `config.py` 的模块注释里。

## 两项关键适配（针对 OCS 的匹配与误抓）

### 1. 答案对齐：避免「选项长得不一样」被跳过

OCS 拿到答案后不是直接采用，而是要过一道四阶段匹配
（源码 `packages/core/src/core/worker/resolvers/single.ts`）：

| 阶段 | 规则 |
|---|---|
| 1 | 归一化后 `答案 === 选项`，或 **`答案.includes(选项)`** |
| 2 | Dice 相似度 **> 0.6** |
| 3 | 答案是单个 `A`/`B`/`C` 字母 |
| 4 | 多片段合并后重试 |

注意阶段 1 的方向是「**答案包含选项**」。所以当选项是「爱因斯坦的相对论」而模型答「相对论」时，
方向相反，相似度仅约 0.33，**OCS 会直接丢弃这道题**——这就是"答案和选项长得不一样就跳过"的原因。

服务端因此加了 `matching.align_one()`，把模型答案改造成 OCS 认得的形态：

1. 原文相等（含 `#`、`//` 这类符号答案）→ 返回该选项原文
2. 归一化后相等 → 返回该选项原文
3. 答案是某选项的子串且**只命中一个** → 返回该选项原文
4. 相似度 > 0.6 → 返回该选项原文
5. 都不满足 → **返回 `None`，调用方把这一段丢掉**

第 5 步是后来改的，原来这里会"总能返回点东西"（挑字符重合度最高的选项）。
后果见下一节。

同时在 prompt 里明确要求"**答案必须是选项原文照抄，禁止同义改写或概括**"。

#### 为什么"对不上就丢掉"比"凑一个"好

原来最后一级兜底是「取相似度最高的选项」。模型答偏的时候，这一级就会把一个
**错误** 的选项交给 OCS 点下去。多选题尤其明显：几段答案被兜底到同一个选项，
OCS 点两下（选中又取消），页面上的勾和答题面板的状态就对不上了——
用户看到的就是「明明都选了，面板还显示未选」。

改完之后：对不上的段直接丢。少点一项只是没答全，点错一项会把对的也带偏。

另外多选还多了一步：模型不用 `#` 分段、把几个正确选项抄成一句话时，
`matching.options_in_text()` 会把这句话里包含的选项原文挑出来，逐个还原。

#### 答案里不能出现 `#`、`|`、`;`、`；`

OCS 的 `splitAnswer` 默认分隔符是：

```js
['===', '#', '---', '###', '|', ';', '；']
```

答案里出现其中任何一个，都会被切成多段。最典型的一道题：

> 在 Python 中，用于表示单行注释的符号是？

正确答案就是 `#`。但 `"#".split("#")` 得到两个空串，过滤后是空数组，
OCS 判定这道题没答上，页面显示「无法选择」。实测缓存里有 3 条这样的答案。

现在的处理：`llm._is_separator_only()` 认出这种"整个答案就是分隔符"的情况，
改用**选项标号**返回（如 `A`），走 OCS 阶段 3 的纯字母兜底。
选项正文外面包的反引号、引号也会先剥掉再比对（`matching.trim_wrap()`），
所以 `A. \`#\`` 这种写法也能命中。


实测 10/10 通过（用 OCS 官方源码的算法当裁判）。

#### 多选答案去重

OCS 答多选题是「逐个点选项」：拿到 `甲#乙#丙` 就点甲、点乙、点丙。
如果同一段出现两次，它会把同一个选项点两下——第一次选中，第二次取消选中，
状态对不上，页面就卡在「等待顺序答题中」不再往下走。

这种重复很容易产生，而且是在**对齐之后**才出现的：模型给的两个不同表述
被对齐到同一个选项，结果就重复了。所以去重放在对齐之后做（`llm.dedupe_parts()`）：

```
模型输出  甲#甲#乙#乙#丙
对齐后    甲#甲#乙#乙#丙
去重后    甲#乙#丙          ← 送给 OCS 的最终答案
```

**只对多选题去重**。填空题的多空答案允许相同（两个空都填「人民」是合法的），
去重会把第二个空的答案吃掉，所以 `completion` 不经过这一步。

#### 判断题必须返回「正确」或「错误」

OCS 判判断题不看选项文本，只看答案里有没有「对/错」类词
（`resolvers/judgement.ts`）：

```ts
const answerShowCorrect   = answers.find((a) => matches(a, CORRECT_WORDS));
const answerShowIncorrect = answers.find((a) => matches(a, INCORRECT_WORDS));
if (answerShowCorrect || answerShowIncorrect) { ...返回对应选项... }
return { finish: false };        // ← 落到这里，页面显示「无法选择」
```

`matches()` 是**精确相等**，不是包含。所以答案写成选项标号 `B` 是无效的——
`"B"` 不等于任何一个正确/错误词，OCS 认为这道题没答上，选项保持空白。

实测踩过这个坑：13 道判断题缓存里有 4 道存的是 `B`，页面上全是空的，
而答案本身是对的（B 就是「错」），只是格式没对上。

服务端因此有 `llm.normalize_judgement()`：

1. 答案里有词 -> 直接用（**先判「否」再判「是」**，否则「不正确」会被「正确」抢走）
2. 只有标号（`B`、`选B`、`B.`）-> 取出该选项的正文，再判一次
3. 与某个选项正文相同 -> 判该选项
4. 都判不出来 -> 原样返回，宁可让 OCS 跳过也不瞎猜

第 2 步必须按选项正文判断，不能假设 A=对、B=错——选项顺序有可能是反的。
实测 12/12 通过，包括顺序反转的用例。

#### 简答题不能用 `#` 分段

OCS 见到 `#` 就当「多个空」，进入顺序填写模式，挨个找输入框往里填。
简答题页面通常只有一两个输入框，填到第二段就找不到了，**这道题卡住不动**，
后面排队的题目全部显示「等待顺序答题中」，看起来像一道都没答上。

所以 `llm.ask()` 最后有一道判断（`should_split()`）：

| 题型 / 题面 | 答案格式 |
|---|---|
| 多选 | `#` 分段（OCS 的硬要求） |
| 填空且题面有 ≥2 个 `____` | `#` 分段 |
| 其余（简答、单空填空） | 顿号连成一段 |

注意**只用下划线数空位，不用括号**——括号在多选题题干里太常见
（「……包括（）」），拿它当空位会把多选题误判成填空。

另外 `detector.py` 对 `completion` 的格式检查也放宽了：原来要求题面必须以
`___`/`。`/`？` 收尾，「简述新民主主义革命的三大法宝及其相互关系」这种
既没空位也没标点的题会被当成非题目直接跳过，连答题机会都没有。
现在「简述/论述/试述/请/如何/怎样…」开头也算合法题面。

#### 简答题要有内容：单独一套 prompt

简答题原来和选择题共用一份 prompt，而那份第 2 条写死「只输出答案本身，
不要任何解释」，模型严格执行，简答就只剩关键词：

| 题目 | 改之前 | 改之后 |
|---|---|---|
| 简述新民主主义革命的三大法宝及其相互关系 | `统一战线、武装斗争、党的建设`（14 字，**相互关系没答**） | 187 字，三个法宝 + 三者关系的完整论述 |
| 请简述 Python 中列表和元组的区别 | `列表可变，元组不可变`（10 字） | 四方面区别（可变性/语法/性能/用途）+ 字典键的补充 |

现在 `detector.is_short_answer()` 先把简答从填空里分出来
（必须是 `completion`、题面无 `____` 空位、且带「简述/说明/区别/关系/如何…」这类措辞），
再分两套走：

| | 选择题 / 判断 / 填空 | 简答 / 论述 |
|---|---|---|
| prompt | `SYSTEM_PROMPT` | `SYSTEM_PROMPT_LONG` |
| max_tokens | 512 | 800 |
| 清洗 | 取首行、把 `;`｜`\|` 统一成 `#` | 多行**全部保留**并合并成一段 |
| 选项对齐 | 走 `align_one` | 不参与 |
| 分隔符 | 多选必须用 `#` | `#` 换成全角 `＃`，`；` 换成句号 |

**「取首行」这个坑值得单独记一笔**：原来 `clean()` 里有一句无条件的
`ans.splitlines()[0]`，模型分三行写的简答只有第一行活下来。
这是"简答答得太简单"最直接的元凶，比 prompt 的影响还大。

还有一句也删了：

```python
if "#" in ans:
    ans = re.sub(r"\s*[;；,，]\s*", "#", ans)   # 逗号变 #
```

它只看答案里有没有 `#`，有就把**全篇中文逗号**换成 `#`，再由 `join_as_text`
补成顿号，产出「我们必须坚持而不能离开社会主义、第二、我国的……」这种病句。
缓存里 3 条是这样坏掉的。现在只有选择题才会做分隔符归一化。


### 2. 非题目拦截：避免把 PPT 正文当题目搜

OCS 的 `buildAnswererEnv` 里有这么一句：

```ts
const env = { type: ..., title: params.title, options };
```

**标题文本原样透传，不做任何过滤**。所以课件页/说明页上选择器抓到的 PPT 正文，
会被整段传给题库，服务端只能对着大段课件问模型，既浪费额度又答非所问。

服务端加了 `_looks_like_question()` 提前拦截，命中则返回 `code=0`（OCS 会回退其他题库）。

判定分三档，越往后判据越弱、规则越严：

| 档位 | 情况 | 规则 |
|---|---|---|
| 一档 | 带了 ≥2 个选项（单选/多选/判断） | 只看长度 ≤200 字、行数 ≤6 行，**关键词黑名单完全不生效** |
| 二档 | 填空题 / 简答题 | 有空位（`____`）、或以标点收尾、或以「简述/论述/请…」开头，满足其一即放行 |
| 三档 | 无选项的其他情况（课件标题、说明文字） | 长度 ≤120 字、行数 ≤3、不命中课件关键词 |

**一档为什么不再看关键词**：真题题干里出现「总结」「概述」「首先」「学校」「专业」
这类词太常见。曾有真题「毛泽东在《〈共产党人〉发刊词》中总结的……三大法宝包括（）」
带了完整的四个选项，却因为一个「总结」被一票否决，OCS 显示「本地AI题库 共 0 个结果」。
带了 A/B/C/D 的文本基本只可能是题目，PPT 正文不会给自己编四个选项。

反过来，PPT 的栏目标题（「本章小结」「概述」）没有选项，自然落到三档被拦下。

控制台新增「**非题目跳过**」计数，可以直观看到拦了多少。

实测 20/20 通过：10 个真实题目（含各种关键词）全部放行，10 个课件正文/异常文本全部拦下。

> 说明：OCS 侧的元素选择器行为无法从服务端改变，这里是**在服务端兜底**。
> 如果仍有漏网，把被抓到的文本特征补充进 `_NON_QUESTION_HINTS` 即可。

## 接入 OCS

启动后，在 OCS 网课助手的设置里，题库地址填：

```
http://127.0.0.1:8000/query
```

若在 `.env` 里设置了 `API_TOKEN`，OCS 的题库设置里也要填同一个值。

> 服务同时支持 GET 和 POST，OCS 用哪种都能正常工作。

### 一键复制配置（推荐）

打开控制台 `http://127.0.0.1:8000/`，在「接入 OCS」区块点**复制**按钮，
会得到下面这段 JSON，粘贴到 OCS 设置的「题库配置填写/修改区」保存即可：

```json
[
  {
    "url": "http://127.0.0.1:8000/query",
    "name": "本地AI题库",
    "method": "get",
    "responseType": "json",
    "type": "GM_xmlhttpRequest",
    "data": {
      "title": "${title}",
      "options": "${options}",
      "type": "${type}"
    },
    "handler": "return (res)=> res.code === 1 ? [res.data.question, res.data.answer] : undefined"
  }
]
```

### 三个字段为什么这样写

按 [OCS 官方文档](https://docs.ocsjs.com/docs/other/api) 和
[源码 `answer.wrapper.handler.ts`](https://github.com/ocsjs/ocsjs/blob/5.0/packages/core/src/core/answer-wrapper/answer.wrapper.handler.ts) 逐一确认：

| 字段 | 值 | 原因 |
|---|---|---|
| `type` | `GM_xmlhttpRequest` | **最关键**。默认的 `fetch` 受浏览器同源策略限制，OCS 页面在 `chaoxing.com` 等域名下时请求不到 `127.0.0.1`。必须用油猴的跨域 API。 |
| `responseType` | `json` | 源码第 154 行实际读取的是 `responseType`，`contentType` 只是历史遗留的兜底。显式写 `responseType` 更稳妥。 |
| `handler` | 见上 | OCS 用 `Function(handler)()` 构造并立即调用，传入请求响应。我的服务返回 `{code, data:{question, answer}}`，所以取出 `[question, answer]` 即可。 |

另外两点：

- **多选题答案用 `#` 连接**。OCS 要求多选题答案必须是特殊符号分隔的字符串而非数组，
  服务端的 `_clean()` 已统一处理成 `#` 分隔，直接满足要求。
- **`data` 里的 `${title}` 等占位符**由 OCS 替换成真实题目；token 则直接拼在 `url`
  查询串上（`resolvePlaceHolder` 只替换占位符，静态值原样保留，且 GET 请求时
  `data` 会覆盖 URL 同名参数，故 token 不放 `data` 里）。

### 配好后怎么验证

1. 控制台「手动测试」框输一道题 → 能出答案，说明 Key 和服务正常
2. 看控制台「运行数据」的**累计查询**有没有涨 → 涨了说明 OCS 真的在请求你的服务
3. **缓存命中**跟着涨 → 重复题目在走缓存，没在重复花钱

如果第 2 步数字不涨，说明 OCS 没连上，问题在跨域或服务地址，不在答题逻辑。

## 网页控制台

浏览器打开 `http://127.0.0.1:8000/`，可以看到：

- 服务状态、当前模型
- 累计查询 / 缓存命中 / 实际调用 API / 已缓存题目 / 非题目跳过 / 失败次数
- 最近 20 条请求（内存，重启即清）
- **缓存题目列表**：真实存进 SQLite 的题，可按题干或答案搜索，显示命中次数和最后时间
- 一个手动测试框，可自己输题目验证答案质量

页面是 `web/` 下的三个静态文件，数据由 `GET /api/status` 和 `GET /api/cache` 取回。
后端不拼 HTML，所以改样式只动 `style.css`，改布局只动 `index.html`。

页面每 5 秒刷新一次统计和两个列表，输入框不会被冲掉；正在搜索框里打字时
缓存列表暂停刷新，否则光标和滚动位置会被打断。

### 「最近请求」和「缓存题目」的区别

| | 最近请求 | 缓存题目 |
|---|---|---|
| 存哪 | 内存 `deque(maxlen=20)` | SQLite `answers` 表 |
| 活多久 | 重启就没 | 一直在 |
| 记什么 | 每次请求的结果（含被跳过、空题、失败） | 只有答成功、真正存下来的题 |
| 用途 | 查「OCS 到底有没有把题发过来」 | 查「我搜过哪些题、答案是啥」 |

## 排查：统计一直是 0

先看启动横幅里的**数据库路径**。项目里可能同时存在多个 `cache.db`
（换过目录、留了旧副本），看错库是最常见的误判：

```
  [OK] 数据库    : C:\...\OCS-AI-Question-Bank\cache.db
       已有 12 道题的缓存，统计沿用上次的记录
```

然后看「最近请求」：

| 看到什么 | 说明 | 下一步 |
|---|---|---|
| 一条记录都没有 | 请求没到服务端 | 查 OCS 里题库有没有启用、地址端口对不对、油猴跨域是否被拦 |
| 全是「空题」 | OCS 传来的 `title` 是空的 | 检查题库配置里的 `${title}` 占位符有没有写错 |
| 全是「跳过」 | 抓到的是课件正文 | 把那条文本的特征词补进 `server/detector.py` 的 `_NON_QUESTION_HINTS` |
| 有「成功」但页面刷得慢 | 正常，OCS 与页面刷新不同步 | — |
| 全是「失败」 | Key 没配或模型调用报错 | 点「保存并测试」看连通性 |

> 空标题的请求现在也计入「累计查询」，并单独显示在「空标题」那一格。
> 原来空标题直接返回、不计数，一旦占位符失效，统计会永远显示 0，看起来像服务没收到请求。

## 排查：改了代码，答案还是旧的

答案链路上有**三层缓存**，改完代码只清了中间一层是不够的：

| 层 | 在哪 | 怎么清 |
|---|---|---|
| 1. Python 进程 | 内存里的模块 | 关掉黑窗口重启，改代码不会热加载 |
| 2. 本服务 SQLite | `cache.db` 的 `answers` 表 | 删行或删库；缓存键不含 prompt 版本，旧答案会一直用下去 |
| 3. OCS 自己的题库缓存 | 浏览器本地存储 | OCS 面板 → 通用 → 拓展应用 → **题库缓存** → 清空 |

第 3 层最容易被忽略：OCS 开着「题库缓存功能」时，答过的题直接从本地取，
**根本不会再请求题库**。这时候本服务的「累计查询」不涨、「最近请求」没新记录，
看起来就像改的东西没生效。

判断方法很简单：看控制台的「最近请求」。你要验的那道题如果压根没出现，
问题在 OCS 那一侧（第 3 层）或者进程没重启（第 1 层），不在答题逻辑里。

## 接口

### `GET/POST /query`

| 参数 | 说明 |
|---|---|
| `title` | 题目文本 |
| `options` | 选项，每行一个 |
| `type` | `single` 单选 / `multiple` 多选 / `judgement` 判断 / `completion` 填空，也兼容数字 `1`~`4` |
| `token` | 访问令牌（设置了 `API_TOKEN` 时必填） |

```bash
curl "http://127.0.0.1:8000/query?title=%E9%B8%A6%E7%89%87%E6%88%98%E4%BA%89%E5%8F%91%E7%94%9F%E5%9C%A8%E5%93%AA%E4%B8%80%E5%B9%B4%EF%BC%9F&options=A.%201840%E5%B9%B4%0AB.%201842%E5%B9%B4&type=single"
```

```json
{"code": 1, "data": {"question": "鸦片战争发生在哪一年？", "answer": "1840年"}, "message": "请求成功"}
```

`code=0` 表示未答上，OCS 会回退到其他题库，不会中断刷课。

### `GET /health`

健康检查，返回 `{"status":"ok","model":"...","has_key":true}`。

### `GET /stats`

查询统计，JSON 格式。

### `GET /api/status`

控制台用的汇总：是否就绪、模型、端口、令牌状态、脱敏 Key、七个统计数
（含「空标题」），数据库文件路径与大小，最近 20 条请求记录
（`recent`），以及可直接粘贴到 OCS 的配置 JSON（`ocs.url` / `ocs.config`）。

### `GET /api/cache`

缓存题目列表，按最近命中时间倒序。参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `q` | 空 | 关键词，同时匹配题干和答案（`LIKE`，`%` `_` 已转义） |
| `limit` | 100 | 最多返回多少条，上限 500 |

```json
{"code": 1, "total": 63, "items": [
  {"title": "...", "answer": "...", "hits": 3, "updated": 1761187200}
]}
```

`total` 是**过滤后**的总数，所以搜「共同富裕」时显示的是搜索结果数，
不是全库数。本题库只存题干和最终答案，不存选项——选项参与了题目指纹，
但没单独留一列。

### `POST /api/config`
网页上保存配置。请求体：

```json
{"api_key": "sk-...", "base_url": "https://api.deepseek.com/v1", "token": ""}
```

写回 `.env`，立即生效不用重启，并顺手发一次真实请求测试连通性。
返回 `{"code":1,"tested":true,"message":"已保存"}`。

> **不生成 `.env.bak` 备份**。`.env` 里是明文 Key，多留一份副本就多一处泄露面；
> 这份备份唯一的用途是从写坏的文件里恢复，而文件只有十几行，重新粘一次比翻备份快。

清除已保存的 Key 用独立字段，不要靠传空串：

```json
{"clear_key": true}
```

返回 `{"code":1,"cleared":true,"tested":false}`，`.env` 里那一行会被写成空值。
页面上的「清除已保存的 Key」按钮就是调这个接口，点之前有二次确认。

> 为什么要单独一个字段：`save_config()` 用 `None` 表示「这个字段不改」，
> 而 JSON 里「没传」和「传空字符串」都能落到空值上。靠空串猜意图，
> 迟早出现「想清除结果什么都没发生」的静默失败。

## 注意事项

- **建议设置 `API_TOKEN`**。服务默认监听 `0.0.0.0`，同局域网的人知道你 IP 就能盗用额度。
- `.env` 含 API Key，不要提交到公开仓库。`.gitignore` 已经把 `.env`、
  `cache.db`、`__pycache__/`、`.workbuddy/` 全部排除。
- 已内置代理绕过（`ProxyHandler({})`），本机装有代理软件也不会影响请求。
- 端口被占用时，改 `.env` 里的 `PORT` 即可。
